# WCA-Inspired Demo Dataset

A small, coherent, populated dataset modelled on the World Cube Association (WCA), delivered as 27 neutral UTF-8 CSV files. It is built from the official WCA Results Export, the public WCA API v0, public WCIF, and the WCA Regulations (version April 1, 2026). It is intended for MySQL, MongoDB or Neo4j demos, not for production or official WCA use.

- 15 competitions
- 1,770 persons
- 13,746 results and 61,311 attempts
- 8,146 scrambles and 8,760 scramble sequences
- 1,343 registrations and 10,169 event selections

## Quick Start

```bash
# Regenerate all 27 files in data/ (Steps 1-7, in order)
python3 pipeline/run_all.py

# Regenerate and run the full validator
python3 pipeline/run_all.py --validate

# Validate the existing files only
python3 pipeline/validate.py
```

Python 3.10+ is required. The pipeline uses only the standard library. A clean run needs network access to the WCA sources; the delivered `cache/` avoids re-downloading and freezes the source snapshot.

`run_all.py` exits `0` when all 27 data files are generated. `--validate` exits `1` because 13 known source-gap violations remain (R4 and R12; see below).

### Pool rule

Competitions with more than about 300 competitors use a pool:

- everyone who reached the final of any event (`round_type_id` `c` or `f`), plus
- everyone with `results.person_country_id = India`.

For each pool person, **every round they competed in that competition** is loaded. Real `Position` and record markers are retained; there is no pool flag column. Pool rows: WC2025 4,756, WC2023 3,631, Asian 2024 2,202 = **10,589** of the 13,746 results. The other 8 result competitions are complete.

Max Park (`2012PARK03`) has 36 real results across WC2023 and WC2025.

### Reproducibility

- `Person_No` is assigned deterministically: WCA-ID persons sorted by WCA ID, then no-ID persons by name/country/user id. The registry is saved in `cache/person_registry.json` and shared by Steps 4–7.
- DOB and Email are deterministic hashes of the person key, so re-runs do not shuffle them.
- The upcoming registration timestamps are generated once in Step 3 and reused by Step 5 via `cache/upcoming_registration_plan.json`.
- The export cache is pinned. The filtered caches (`shortlist_results.tsv`, `selected_attempts.tsv`, `selected_scrambles.tsv`) are rebuilt from the export if missing. The pipeline was verified from an empty `data/` and after deleting those three filtered caches; the regenerated 27 files were byte-identical.
- `assigned_as_slots` depends on Group_ID; no synthetic scramble was generated.

## CSV Conventions

- UTF-8; header row; comma-separated; fields containing commas, quotes or newlines are quoted and inner quotes doubled.
- Dates `YYYY-MM-DD`; timestamps `YYYY-MM-DD HH:MM:SS` in UTC.
- Booleans `1`/`0` (`Is_Extra`, `Is_Dual`, `Is_Head_to_Head`, `Guardian_Consent`).
- An empty cell means NULL. The CSVs never contain the text `NULL`.
- Apostrophes and non-ASCII text are kept as published.
- Country IDs are WCA string ids (`India`, `USA`, `Hong Kong`), not ISO2; `ISO2` is a separate column.
- `Person_No` is the stable integer key; `WCA_ID` is nullable for the 17 no-ID persons.
- `Result_ID` is the real WCA export result id, not a generated sequence.

## Provenance

- **REAL**: values copied from the export/API/Regulations — IDs, names, countries, dates, results, attempts, scrambles, rounds, records, team names/emails, region names, delegate statuses, role start dates.
- **DERIVED**: `Person_No`; `Since_Date`; `Round_Number`; `Is_Dual`; `Is_Head_to_Head`; `Last_Day`; `Role_Code`; slot `Group_ID`; `Venue_Name` markdown cleanup; `Status = accepted` for past competitions (inferred from results); `events.Status`; `formats.Trimmed_Per_Side`; `Team_ID = board`; `Kind`.
- **SYNTHETIC**: `persons.Date_of_Birth`; `persons.Email`; `registrations.Registered_At`; `registrations.Guests`; `registrations.Guardian_Consent`; upcoming registration `Status`; 12 `previous_identities.Valid_Until` values; 56 `Since_Date` values derived from the synthetic registration plan.

No synthetic scramble, identity, country or result was created.

### Synthetic data notes

- `Date_of_Birth` is generated to be plausible relative to the WCA ID year (age 6–60 at first competition) or to 2026 for no-ID persons (age 8–60). Do not use it as a real birth date.
- `Email` is synthetic at `example.com`, unique via the Person_No suffix.
- `registered_at` is synthetic and inside the published `[Opens_At, Closes_At]` window; it increases with `Registrant_No`.
- Upcoming statuses are synthetic. The people are real WCIF registrants. Past statuses are `accepted`, inferred from having results.
- `Guests` is synthetic 0–3. `Guardian_Consent` is 1 exactly when the synthetic DOB makes the person under 18 on `Start_Date`.
- 12 previous-identity `Valid_Until` values are synthetic because those identities have no result in this slice; the rest are derived from old-country or current-country result dates.
- 56 `Since_Date` values use the synthetic registration plan for people with no result in the current country but an upcoming registration.

## Known Gaps and Caveats

1. **Organizer schema gap (R4)**: no organization entity. Five competitions have only organization organizers; `competition_organizers` is empty for them.
2. **Delegate supervisor gap (R12)**: eight Central Eurasia delegates have no person supervisor because the published senior is the non-person WCA Board.
3. **R8 long-average rounding**: two 444bf/555bf averages differ from a centisecond recomputation by the nearest-second rule. The export values were retained.
4. **Since_Date**: 8 NULL values (unattached PERSON 1–8) although the schema says NOT NULL; 729 values use the published WCA account-creation date as the “registration date” fallback; 4 values use an old-country result because the person has no current-country result; 56 values use the synthetic registration plan.
5. **Delegate e-mails**: 128 trainees have NULL `WCA_Email` (no published e-mail; you approved nullable). Their `Region_ID` comes from the WCIF role group even though the delegates API has `region_id = null`. The WCA Board delegate row was excluded (no WCA ID/country). 813 delegate/role rows collapse to 766 persons, using the highest current status.
6. **Previous identities**: 31 rows; 1 pure duplicate (`Reto Bubendorf`, Switzerland) was dropped; 12 `Valid_Until` values are synthetic; old names are kept as published, not split into romanized/local.
7. **Staff assignments**: 34,067 WCIF staff rows; 16,304 rows / 314 users are outside the PERSON union and are excluded. 8,251 ASSIGNED_AS rows and 4,848 slots remain. Three competitions with scrambles publish no staff assignments (`BigNBlindBengaluruSep2026`, `DCHyderabadOpenDecember2024`, `IndianFMCChampionship2026`).
8. **Assignment roles**: the slice contains only judge, runner and scrambler assignments. There are no `staff-dataentry`/`staff-announcer` rows, although `staff_role.csv` lists all five roles. `staff-Delegate`, `staff-Checker` and `staff-ScrambleChecker` were excluded.
9. **Slots**: all 4,848 slots are WC2025. Other competitions publish `stationNumber = null`, so their ASSIGNED_AS rows have no slot rows. 2,231 ASSIGNED_AS rows have at least one slot; 6,020 do not.
10. **Scramble completeness**: 100 `(competition, event, round)` pairs have a different number of scheduled WCIF groups than published scramble groups. Example: WC2025 3x3 round 1 has 82 scheduled groups but only 22 published scramble groups (A–V); the other 60 groups have no scrambles. No synthetic scrambles were generated. Conversely, some rounds have more published scramble groups than scheduled groups.
11. **Competition organizers source**: individual organizers are taken from WCIF person roles, not from the API’s organization accounts. Organization-only entries are excluded, which causes the R4 gap.
12. **Competition delegates**: 98 rows. 11 designated delegate rows / 9 WCA IDs were excluded: 3 people are not in PERSON (`2008VIRO01`, `2009OHRN01`, `2014STEI03`) and 6 are no longer current delegates (`2009HILD01`, `2020LONG05`, `2015SUCK01`, `2015NATH01`, `2013GHOD01`, `2014KANN02`). Every competition still has at least one current delegate.
13. **Past registrations**: only result persons are registered, not the full WCIF accepted list. Their event selections are derived from their results, not from the original registration event list.
14. **Upcoming SELECTS**: cancelled/rejected registrations deliberately have no SELECTS rows, creating 7 demo-safe REGISTRATION keys. Pending and waiting-list registrations do have SELECTS.
15. **Registrant order**: `Registrant_No` is deterministic by Person_No, not real registration order. Timestamps are synthetic but increasing.
16. **Per_Attempt**: 12 rounds (333fm and 333mbf) have NULL `Per_Attempt` because WCIF omits their fixed time limits. No event-specific regulation limit was imported.
17. **Trimmed_Per_Side**: `formats.Trimmed_Per_Side = 0` for Best of 5 per your schema, although the export’s trim columns are `1/1` and 333bf Best-of-5 results carry an out-of-format Ao5. R8 still uses the 5-attempt Ao5 rule; results match the export except the two long averages.
18. **Excluded events/formats**: `fto` (Face Turning Octahedron, not in Regulation 9b) and format `h` (Head-to-Head) were excluded as approved. There are 21 events (17 official + 4 retired) and 6 formats. No loaded round uses either.
19. **Head-to-Head**: 0 rounds. `h2h_rounds` is empty for every shortlisted competition.
20. **Main_Event_ID**: `MohaliCubeOpen2026` is NULL although the API says 333, because the cancelled competition has no loaded rounds. Indian FMC and Indian PBQ also have NULL main events.
21. **Websites**: Indian competitions have no external website, so `Website` is the WCA competition page. WC2023/Asian/WC2025 use external sites.
22. **Venue_Name**: markdown link text was extracted and whitespace trimmed. `Venue_Details` is kept verbatim; Indian FMC’s detail contains a Markdown link.
23. **Countries**: 108 rows = 100 referenced + 8 fully unreferenced. Nine countries have no persons and no competitions; Belize is one of them but is referenced only by an old identity. The eight fully unreferenced are Benin, Burkina Faso, Burundi, Central African Republic, Democratic People’s Republic of Korea, Dominica, Federated States of Micronesia, Vatican City.
24. **Recent IDs**: 113 persons have WCA ID year ≥2025; only 1 repeats within 12 months — Person_No 1656 (`2025GIRI02`, Bengal 2025-12-20 → IISER 2026-11-01, 316 days). This is technically “some” but thin.
25. **Demo-safe competition**: only one fully unreferenced competition (`MohaliCubeOpen2026`), short of the requested 5–8.
26. **Team membership omission**: `wat` and `wmt` have no MEMBER_OF rows by design, to provide demo-safe TEAM keys. Their real members are not otherwise added as persons solely for that membership.
27. **Teams**: 18 rows = 15 current + 3 inactive committees (`wdc`, `wdpc`, `wec`). The inactive committees have zero active members. `Kind` is derived from `group_type` and the name suffix.
28. **Regions**: 54 rows = 46 current delegate regions + 8 inactive leaves. Region names are the WCA delegate-region group names, not the `location` strings; 40 of 46 current regions have multiple location strings. The 8 inactive leaves provide the leaf/no-delegate demo keys.
29. **Punctuation/quotes**: 2 persons with apostrophes (`Person_No` 792, 1110) and 2 countries; 370 fields containing commas are CSV-quoted across 353 raw lines. No source name contains a literal double-quote character; “quotes” exist as CSV field quoting.
30. **Local names**: 253 Local_Name values (CJK 181, Hangul 28, Thai 14, Cyrillic 15, Devanagari 6, other 9); 394 person names contain non-ASCII characters.
31. **Live API caveat**: the cache freezes the API/WCIF snapshot. A full re-fetch may change upcoming registrations, assignments or rounds. The export is pinned; the API is not.
32. **`assigned_as_slots` group mapping**: WCIF group numbers are converted to Excel letters (1→A, 27→AA). All station-bearing assignments that survived the PERSON filter mapped to a published scramble group; 0 were dropped for a missing group.
33. **`competitors`**: one row for every person with a non-NULL WCA ID; it is a subtype table, so even the 8 unattached demo-safe persons have COMPETITOR rows.
34. **No organization table**: this is the root cause of the R4 gap and of the exclusion of organization-only competition organizers; adding one is a schema extension, not a data fix.

## Loading Notes

- Load order follows the foreign keys:
  1. `continents`, `countries`, `events`, `formats`, `allows`, `staff_role`, `regions`, `teams`
  2. `persons`, `previous_identities`, `competitors`, `delegate`, `member_of`
  3. `competitions`, `championship_types`, `competition_delegates`, `competition_organizers`, `rounds`, `cumulative_scope`
  4. `registrations`, `selects`
  5. `results`, `attempts`
  6. `scrambles`, `scramble_sequences`, `assigned_as`, `assigned_as_slots`
- Empty fields mean NULL. For MySQL `LOAD DATA`, empty unquoted fields become empty strings by default; map them with `NULLIF(@col,'')` per nullable column, or preprocess to `\N`. For MongoDB/Neo4j, convert empty strings to null.
- Booleans are `1`/`0`, not `true`/`false`.
- Timestamps are UTC strings, not timezone-aware SQL timestamps. Parse as UTC.
- `Country_ID` and `Continent_ID` are string keys; `ISO2` is the separate two-letter code.
- `Person_No` is the person key everywhere; `WCA_ID` is nullable. `Result_ID` is the real WCA result id.
- The `rounds` key is `(Competition_ID, Event_ID, Round_Number)`; the results and scrambles use the same triple.
- `assigned_as_slots` references the first five columns of `assigned_as` plus `Group_ID`.
