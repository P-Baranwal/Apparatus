# Taste — Command Code
- Wants a strict one-step-per-reply cadence: complete a single step, then stop and wait for an explicit "next" before continuing. Confidence: 0.85
- Splits large build tasks into numbered steps and expects the first step (source/feasibility confirmation plus a proposed plan) to stop for approval before any deliverable is produced. Confidence: 0.8
- Insists that no value comes from memory or guessing: verify against the named sources, inspect real headers/structures before mapping them, and report immediately if a source is inaccessible instead of substituting a guess. Confidence: 0.9
- Rejects fabricated or placeholder data (test1, Sample, John Doe, Lorem ipsum, "Person 17"); unanswered values must be left empty and reported as gaps, never invented. Confidence: 0.9
- Likes explicit provenance labelling per value/column (real, derived, synthetic), with synthetic generation confined to separate, clearly labelled code paths and used only where the source genuinely lacks the value. Confidence: 0.85
- Wants conflicts with authoritative reference material (e.g. published rules/regulations) surfaced and reported as deviations rather than silently resolved. Confidence: 0.8
- For anything larger than a small table (~60 rows), prefers a runnable script that fetches and writes files over pasted data; inline output is acceptable only for small tables. Confidence: 0.85
- Specifies Python 3.10+ with a minimal dependency set (standard library plus `requests`), deterministic output (fixed random seed), and cached downloads rather than repeated network calls. Confidence: 0.85
- Expects multi-part deliverables to be one coherent pipeline that shares state (a common registry) rather than independent scripts. Confidence: 0.75
- Specifies deliverable formatting precisely and expects it honoured exactly: UTF-8, ISO `YYYY-MM-DD` dates, `YYYY-MM-DD HH:MM:SS` UTC timestamps, 1/0 booleans, empty cell for NULL (never the literal "NULL"), proper CSV quoting, and original non-ASCII text and apostrophes preserved verbatim. Confidence: 0.85
- Treats a given schema as the source of truth: do not add, rename, reorder or drop columns, and report anything that does not fit instead of adjusting the spec. Confidence: 0.85
- Expects a structured report after each step: file names with expected row counts, per-column provenance, columns left empty and why, deliberately unmatched/demo-safe keys, and every unverified item or deviation. Confidence: 0.8
- When the plan raises numbered open questions, answers them in terse numbered form with a bare decision per item ("1. exclude; 2. exclude; 3. relax them as nullable") and no restated context — so open questions should be numbered, each with a concrete recommended default to accept or reject. Confidence: 0.6
- Expects the generator to be provably complete: every deliverable file produced by a pipeline script (no file left over from exploration/probing), runnable from an empty checkout via one orchestrator entry point, with completeness proven by clean-room regeneration + byte-identical diff rather than asserted; challenges "is everything generated?" claims and wants the verification actually performed. Confidence: 0.75
- Wants project-level documentation (README at the repo root) that is exhaustive rather than tidy: a complete inventory of everything useful plus an explicit, numbered catalogue of every caveat/gap, including unresolved validation failures, source limitations, synthetic fields and demo-safe key shortfalls, instead of a short summary that hides them. Confidence: 0.65
- When real source data conflicts with stated schema constraints, resolves it by relaxing or dropping rather than fabricating: NOT NULL columns the source never publishes become nullable instead of being filled with synthetic values, and data the authoritative spec does not sanction (extra events/formats found only in the export) is excluded rather than kept. Confidence: 0.65
